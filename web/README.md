# web — Ashara Signage frontend

Vite + React 18 + TypeScript (strict). Talks directly to PostgREST; there is
no Node/Express layer. Auth is a `login()` Postgres function returning a JWT;
RLS is the security boundary.

## Stack (pinned)

- vite + @vitejs/plugin-react
- react 18 + react-dom 18
- typescript 5 (strict)
- tailwindcss 3
- react-router-dom 7
- @tanstack/react-query 5
- zustand 5
- zod 4
- react-hook-form 7
- jwt-decode 4
- lucide-react

No axios. No `@supabase/supabase-js`. No shadcn/MUI.

## Setup

```bash
pnpm install
cp .env.example .env.local   # already created with localhost defaults
pnpm dev
```

Open http://localhost:5173 → redirected to `/login`.

### `pnpm types:generate` notes

PostgREST 12 still emits Swagger 2.0; `openapi-typescript` v7 only accepts
OpenAPI 3.x. `scripts/generate-types.mjs` fetches the spec, runs
`swagger2openapi`, then pipes the converted spec into `openapi-typescript`.
Override the source URL via `POSTGREST_URL` env var.

If PostgREST is offline, the script exits non-zero and `src/types/db.ts`
remains as the last successful generation — safe to commit.

## Architecture

```
src/
├── api/             # (Step 3+) feature-scoped HTTP fns
├── components/      # AppShell, TopBar, Sidebar, StatusPill, TypeBadge,
│                    # RoleBadge, EmptyState, Toaster, RequireAuth,
│                    # EventSwitcher, Skeleton
├── features/        # (Step 3+) feature folders
├── hooks/           # (Step 3+) reusable hooks
├── lib/
│   ├── api.ts       # fetch wrapper: db.from(t).select/insert/update/delete,
│   │                # db.rpc(name, args). Throws ApiError.
│   ├── auth.ts      # useAuth() Zustand store; jwt-decode; login/logout
│   └── rbac.ts      # isSuperAdmin / canApprove / canChangeStatus / etc.
├── pages/
│   ├── Login.tsx    # ITS + password → db.rpc('login', ...) → redirect by role
│   ├── Signup.tsx   # placeholder, real wizard in Step 3
│   ├── Stub.tsx     # placeholder shown by every not-yet-built route
│   └── admin/Events.tsx  # Step-2 smoke screen reading /events
├── stores/
│   ├── eventScope.ts # super_admin event filter (persists 'all' or uuid)
│   └── toast.ts     # toast queue + useToast()
├── types/db.ts      # generated by pnpm types:generate
├── App.tsx          # route table; RequireAuth gates per role
├── main.tsx         # providers (QueryClient, BrowserRouter)
└── index.css        # CSS variables from prototype + .pill / .badge-type rules
```

### Design tokens

All colour / radius / shadow vars in `src/index.css` come straight from
`signage_app_prototype_v2.html`. Tailwind utilities are mapped onto the
same vars in `tailwind.config.js` (e.g. `bg-info-bg`, `text-muted`,
`border-border-strong`, `rounded-lg`).

### State boundaries

- **Server state** → TanStack Query. Never duplicate into Zustand.
- **Client state** (toggles, selections, persisted prefs) → Zustand or
  local `useState`.
- **Auth** → `useAuth` Zustand store, hydrated from `localStorage` JWT on
  first read.

### Adding a new screen

1. Need data not exposed by an existing endpoint? Add a Postgres view or
   RPC in `db/` first — do not stitch joins on the client.
2. Add a `db.from(...).select()` call inside a TanStack Query hook in
   `features/<area>/hooks/`.
3. Build the component using the shared primitives (`StatusPill`,
   `TypeBadge`, `EmptyState`, `Skeleton`).
4. Wire a route in `App.tsx`, gated by `<RequireAuth allow={[...]}>`.
